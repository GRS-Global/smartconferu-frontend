# QA fixture inventory

Goal: make the prototype and the Next.js app show comparable data without touching the prototype, `.env*`, Supabase or any business logic.

## How both apps are started for QA (no env file is edited)
| App | Command (from the repo) | Data |
|---|---|---|
| Prototype, port 5180 | `VITE_USE_DATABASE=false npx vite --port 5180 --strictPort` (in `author-journey/`) | Prototype's own in-source sample data, demo sign-in via localStorage `grs_logged_in` / `grs_auth_mode` (set by `qa/lib.mjs`) |
| Next.js, port 3100 | `NEXT_PUBLIC_DATA_SOURCE=mock NEXT_PUBLIC_MOCK_FIXTURES=parity NEXT_PUBLIC_PROTOTYPE_URL=http://localhost:5180 npx next dev -p 3100` | Typed mocks in `src/mocks`, parity mode on |
| Next.js auth pages, port 3101 | `NEXT_PUBLIC_DATA_SOURCE=supabase NEXT_PUBLIC_SUPABASE_URL=http://127.0.0.1:9 NEXT_PUBLIC_SUPABASE_ANON_KEY=qa-dummy-key ...` | **No data and no backend**: the URL is a discard port, so nothing real can be contacted. Only used so login / register / reset-password render *enabled* forms (mock mode disables them). |

Both Next instances must run from a **copy** of `frontend/` when your own `next dev` is already running (Next allows one dev server per folder): copy without `.next`, `qa`, `.git` and **without `.env.local`**, then give the copy its own `node_modules`. (A junction to the original `node_modules` is rejected by Turbopack.)

## Fixtures added (Next.js mock layer only; default behaviour unchanged when the env var is absent)
| File | What | Source of truth |
|---|---|---|
| `src/mocks/parity-conferences.ts` (generated) | The prototype's 50 sample conferences: id, number, acronym, name, roles, dates, country, pinned, archived/active for the frozen date | Generated by `qa/gen-parity-fixtures.mjs`, which reads `src/author-journey.jsx` (`MY_ROLES`, `EXTRA_CONFERENCES`) read-only and evaluates the prototype's own generator. Re-run it if the prototype's conference data changes. |
| `src/mocks/parity.ts` | `mockSlug()`: in parity mode the id `isbm2026` is answered by the existing rich demo conference `demo-dsai-2027` | Hand-written alias |
| `src/mocks/conferences.ts` | In parity mode the dashboard lists the 50 prototype conferences; per-conference paper / review / certificate counts are empty | - |
| `src/mocks/{author-submissions,chair,reviewer}.ts` | Look conference ids up through `mockSlug()` | - |

## Determinism
- Clock frozen to `2026-11-03T10:00:00Z` in every browser context (`qa/lib.mjs`); archived/active is computed for the same date in the generator.
- UTC, en-US, DPR 1, reduced motion, animations/transitions disabled, fonts awaited, Next dev badge hidden.
- Fixtures have no randomness.

## What is NOT matched (and why it matters)
| Gap | Effect on results |
|---|---|
| Prototype papers (~100 in-source records), reviewers, reviews, activity, emails are not mirrored | Workspace pages show **different rows**: the prototype shows its sample papers, Next.js shows the demo ones. Compare layout/components, not row content or counts. Control counts on list pages (e.g. 1,024 vs 45 on Chair Submissions) are driven by row counts. |
| Per-conference dashboard counts | Numeric cells on My Conferences differ. |
| Signed-in user profile | Prototype signs in as the sample person; Next mock mode has no accounts, so **Profile, Settings and Complete profile show "not available in mock data mode"** and cannot be compared without a live or fake Supabase. |
| Paper-level pages (`/submissions/[paper]/*`, review form) | Need identical paper ids on both sides; not built. |
| Public author profile | Needs the migration-0027 database function. |
